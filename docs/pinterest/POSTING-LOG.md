- Initial publication used the owner's authenticated Chrome session after Pinterest's security password reset had been resolved. The browser profile the owner identified was used to locate the correct session; credentials are not recorded here.
- The 2026-10-19 batch initially used temporary Windows UI automation against the owner's Chrome. When the user moved that shared browser to another task, a separate ephemeral Playwright Chrome session was opened without copying the user's profile or cookies. The owner manually signed in there, and final edits/checks used the authenticated isolated session. No connected Pinterest/Metricool publishing integration was used.
- Villa Fabulosa's Business account was confirmed in Business Hub. The website was still unclaimed.
- Use an authenticated isolated session for future Pinterest publication or edits; obtain manual sign-in again if necessary. Local asset preparation does not require browser access. Do not automate unrelated tabs in the user's shared browser.
- On 2026-10-25, the owner manually signed in to a dedicated persistent Playwright profile stored outside the repository. No existing Chrome profile or cookies were copied.
- The legacy `/pin-creation-tool/` redirected to an Idea-ad flow at `/idea-pin-builder/` on 2026-10-25. The observed **Create Pin** navigation opened regular organic `/pin-builder/`. All four new Pins used the regular flow with Ad-only Off and immediate publication. No native topic selector was available there or in Edit Pin; saved description hashtags are separate from native topics.
- Pin 001 initially had a blank saved description. It was corrected in Edit Pin and verified after a full reload on 2026-10-18. Native typing, blur, Save and post-reload readback are required because changing a UI automation value alone did not reliably persist the description.
- During a later Pin 001 edit, Playwright `.fill()` appended a duplicate description. Readback caught the duplication before Save; native `Ctrl+A`, typing and blur corrected it. All four final captions were then saved and exactly verified after full reload. Do not trust `.fill()` alone on the editable description control.
- During Pin 005 preparation on 2026-10-20, filling Link after the description truncated the caption. Exact pre-publication readback caught this before publication. Setting Title and Link first, then typing Description last and blurring, corrected the form. Verify the entire caption before publication and again after full reload; field order alone does not prove a saved result.
- Pin 002 showed an automatic public AI-modified badge even though its manual disclosure was saved Off. The owner then explicitly chose to continue generated designs with manual disclosure Off for the remaining two Pins. Final checks found badges on all four Pins despite manual Off. Do not promise badge removal or strip metadata.
- Publish one at a time, capture the public URL, and check for an existing Pin before retrying uncertain submissions to avoid duplicates.
